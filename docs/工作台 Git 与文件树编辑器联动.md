# 工作台 Git：侧栏、文件树和编辑器怎么连在一起

这份文档描述 **当前代码实际在做什么**，给后续审阅用。目标是让阅读者判断：Git 页、文件树、编辑器之间有没有对不上，操作会不会丢改动，反馈够不够。

范围是项目工作台左栏的「文件 / Git / 大纲」，以及它们和中间编辑器的联动。聊天里的 diff 卡片、智能体 inline diff 的接受/撤销，只在和 Git 状态刷新撞在一起时提到，不展开那套协议。

## 1. 左栏三个 tab

工作台左边是 `workspace-sidebar`。标题下面一排：

| 按钮 | `leftTab` | 里面是什么 |
|---|---|---|
| 文件 | `files` | 资源管理器：每个工作区一棵文件树 |
| Git | `git` | `SourceControlPanel`：变更列表、提交、分支和同步、提交图。按钮上有变更数量 |
| 大纲 | `outline` | 当前打开文件的符号，点一行让编辑器滚到那一行 |

默认是「文件」。三个面板里，Git 用 `v-show`，切走不销毁，提交说明草稿还在。文件和大纲用 `v-if` / `v-else-if`，切走会卸掉。

标签条放不下时两边出左右箭头（上一项 / 下一项），顺序固定是文件 → Git → 大纲。竖滚轮在标签条上改成横向滚。没有快捷键切换这三个 tab。

点「Git」时，如果有未保存的编辑器标签，先 `window.confirm`：「打开 Git 会先保存未保存的 {文件名}。是否保存并继续？」多个文件则说个数。取消会留在原来的 tab，不写盘。确认后 `persistDirtyEditors()` 把这些脏标签写回磁盘，写失败就停在这一步，不再往下刷新。没有脏标签时直接刷新。

## 2. 哪些仓库真的有 Git 数据

界面上每个工作区都会出现，但后端状态接口不是全给。

`list_project_git_status` 只保留 `kind == "git"` 且 `isolationMode == "worktree"` 的工作区。暂存、撤回、提交、fetch、pull、push、sync、切换分支、提交图、读某个修订版本，入口都再查一次 `get_git_workspace`，不是这种工作区就返回：

> 源码管理仅支持隔离的 Git Worktree 项目

`git_index_file`（编辑器色条用的暂存区内容）**不走这道过滤**，按 `work_path` 直接 `git show :./路径`。

工作区在界面上的三种样子（文件树头和 Git 页头同一套文案）：

| 模式 | 判定 | 药丸 | 副标题 | 悬停说明 |
|---|---|---|---|---|
| Worktree | Git 且隔离模式是 worktree | Worktree | `{分支} · 独立工作树` | 独立检出，不会改动原仓库当前分支 |
| 当前分支 | Git 但不是 worktree | 当前分支 | `{分支} · 正在改真实分支` | 提交会写回原仓库 |
| 非 Git | `kind !== "git"` | 非 Git | 隔离副本或原目录 | 不是 Git 项目 |

分支名优先用状态接口返回的 `repository.branch`，没有就用工作区上存的 `workspace.branch`。

「当前分支」这种仓库：**头上的警告文案写了，但状态列表里没有它。** Git 页展开后，既不是「这不是 Git 项目」那张卡片，也没有提交框和文件列表（加载结束后 `repository` 仍是空）。文件树上也不会有 Git 字母，因为字母来自这份被过滤掉的状态。编辑器色条仍可能画，因为它另调 `git_index_file`。

非 Git 文件夹：Git 页展开后只显示「这不是 Git 项目，没有分支、暂存和提交。」加上模式说明。没有提交框。

## 3. Git 页

顶栏是「源代码管理」、列表/文件夹切换、刷新。下面每个工作区一节。只有一个工作区时，节头收成一行：当前分支、ahead/behind、更多操作。多个工作区时，每节先是可折叠的仓库头（名字、副标题、模式药丸），展开后才是同一套分支和操作。

分支按钮列出 `branches`。点一项调用 `gitSwitchWorkspaceBranch`。菜单底部可以新建分支（`window.prompt` 后 `create: true`）。切换前工作区必须是干净的，否则后端拒绝。`direct` 模式在切换、拉取、推送、同步、提交前都要再确认一次。

更多操作：刷新、拉取、推送、获取、切换分支。拉取是 `gitPullWorkspace`，推送是 `gitPushWorkspace`，获取是 `gitFetchWorkspace`。ahead 或 behind 的数字按钮是同步（先 pull 再 push）。

### 3.1 提交框

只在「是 Git，并且状态接口返回了这个仓库」时出现。

| 控件 | 行为 |
|---|---|
| 输入框 | 按工作区 id 存在内存。占位符带当前分支。⌘/Ctrl+Enter 等于点主按钮。光标在开头按上方向键、在末尾按下方向键，翻这一工作区刚提交过的说明 |
| 火花按钮 | title「AI 生成提交信息」。用已暂存 diff 调 `generateGitCommitMessage` |
| 主按钮 | 见下表 |
| 主按钮右边的 chevron | 只在主按钮是「提交」时出现。弹出：提交 / 提交并推送 / 提交并同步 |

主按钮文案由 `scmPrimaryAction` 决定，能提交时优先提交，而不是先发布：

| 条件 | 按钮 | 可点条件 | 点了做什么 |
|---|---|---|---|
| 说明非空且至少一条暂存 | **提交** | 同上 | `git commit -m`。可选再推送或同步 |
| 否则：有远程、没有上游、不在合并中 | **发布分支** | 同上 | 有暂存但说明是空的时先确认，再 push。没有暂存则直接 push |
| 否则：有上游且 ahead 或 behind | **同步更改** | 同上 | pull 再 push。按钮上带 ahead↑ / behind↓ |
| 否则 | **提交**（禁用） | 不能点 | — |

一次只允许一个 Git 操作。被挡住的按钮 title 是「另一个工作区正在执行 Git 操作」。

### 3.2 合并中

`merging` 为真时显示「正在解决合并冲突」和「中止合并」。拉取、获取、同步在合并中不可用。

### 3.3 四组文件

`scmGroups` 按 porcelain 字母拆开。空组不画。一个文件可以同时出现在「暂存的更改」和「更改」（index 和工作区都有字母）。冲突只进合并组，未跟踪只进未跟踪组。

| 组 | 收录 | 组头 |
|---|---|---|
| 合并更改 | 任一侧 `U`，或两侧都是 `A` / 都是 `D` | 撤回全部、全部标记为已解决（`git add` 这些路径） |
| 暂存的更改 | index 不是空格也不是 `?` | 全部取消暂存 |
| 更改 | 已跟踪且工作区有改动 | 撤回全部、全部暂存 |
| 未跟踪的更改 | `?` | 撤回全部、全部暂存 |

组头的暂存/取消暂存只作用于这一组的路径，不再对整个仓库 `git add -A`。

顶栏可以在列表和按目录树之间切换，选择记在 `localStorage` 的 `multara.scm.viewMode`。默认列表、按路径排序。单击一行打开 diff。⌘/Ctrl 点多选，Shift 在同一组里连选。右键对选中项做暂存、取消暂存或撤回。悬停一行可以打开、暂存或取消暂存、撤回（暂存组没有撤回）。

点一行发出 `openChange`，带上组名。工作台打开只读的 Monaco diff 标签，不替换普通编辑标签：

| 组 | 左边 | 右边 |
|---|---|---|
| 暂存 | `HEAD:路径` | 暂存区 |
| 更改、合并 | 暂存区 | 工作区文件。磁盘上没有则右边是空的 |
| 未跟踪 | 空文档 | 工作区文件 |
| 提交图里的文件 | 父提交；新增则左边为空 | 该提交。删除则右边为空 |

二进制文件只显示「无法比较」，不塞进编辑器。Git diff 标签不参与保存，也不会因为撤回而被重读成普通缓冲。

字母仍用 `gitStatusLetterFor`：暂存组看 index，其余组看工作区；合并组显示冲突 C。撤回仍先 `window.confirm`（未跟踪文件是永久删除，未跟踪目录会连内部未跟踪文件一起 `git clean -fd`）。撤回、拉取、同步、切换分支、中止合并之后，不脏的普通编辑标签跟磁盘对齐；脏标签只提示，不覆盖。Git diff 标签排除在这次重读之外。暂存和普通提交不改工作区字节，不重读编辑器。

## 4. 文件树和 Git 的关系

「文件」tab 是资源管理器，不是 Git 视图。Git 只体现在三处：工作区头上的分支副标题和模式药丸、行文字颜色、行尾标记。

### 4.1 工作区头

点头部：折叠/展开这一棵，并选中工作区根。右键空白头：

- 新建文件… / 新建文件夹…
- 刷新资源管理器 / 折叠此项目
- 在文件资源管理器中显示 / 复制路径
- Git 工作区再加一项「复制分支名」。分支用 Git 页当前分支，没有则用工作区记下的分支。两边都空时这项不可点。普通文件夹没有这项。

「刷新」只重读文件树（`loadWorkspaceRoots`），**不**重拉 Git 状态。

### 4.2 行上的 Git 标记

非 Git 工作区整行不算状态。Git 工作区用 `gitRepositories` 里该仓库的 `changes`：

- 文件：路径完全相等则取 `gitStatusLetter`。工作区字母优先，工作区是空格才用暂存字母。冲突优先成 C。
- 目录：该目录自己或 `路径/` 前缀下任一变更。优先级：冲突 C > 新增或未跟踪 U > 删除 D > 重命名 R > 修改 M。

有状态时：

- 整行文字用上面的颜色。
- 文件行尾是字母。
- 目录行尾是一颗 6px 圆点，没有字母。title 是「目录下有 N 处改动」。圆点颜色跟着行文字。文件行尾字母的 title 仍是修改 / 未跟踪 / 新增 / 删除 / 重命名 / 冲突。

另外：diff store 把该路径标成缺失时，行 class 强制 `git-deleted`（红），即使 Git 状态还没回来。

文件树 **没有** 暂存、撤回、提交。那些只在 Git 页。

### 4.3 文件树自己的操作（和 Git 会互相影响）

| 操作 | 结果 | 会不会刷新 Git 字母 |
|---|---|---|
| 单击文件 | 打开到编辑器。已有标签且未保存则不从磁盘重读 | 否 |
| 双击文件 | 打开并钉住标签 | 否 |
| 单击目录 | 展开/折叠并选中 | 否 |
| 拖到聊天或工作台 | 把路径加进聊天输入框，不是 Git 操作 | 否 |
| 右键文件 | 打开、添加到聊天、在访达显示、复制路径、复制相对路径、重命名 F2、删除 Del | — |
| 右键目录 | 新建文件/文件夹、添加到聊天、显示、复制路径、复制相对路径、重命名、删除 | — |
| 重命名 | 改磁盘路径，已打开的编辑器标签路径跟着改 | 会，文件树和 Git 页一起刷 |
| 删除 | 确认后删磁盘。开着的标签关掉 | 会，文件树和 Git 页一起刷 |
| 新建文件/文件夹 | 写磁盘，新建文件会打开 | 会 |
| 工具条「刷新」「全部折叠」 | 重读树 / 收起全部目录和工作区 | 刷新会拉 Git；全部折叠不会 |

资源管理器标题栏：新建文件、新建文件夹（没选中树节点时 disabled）、刷新、全部折叠。

## 5. 编辑器和 Git 的关系

编辑器里和「改了没有」有关的有三套，不要混：

| 信号 | 比的是什么 | 画在哪 |
|---|---|---|
| 标签脏点 | 缓冲区相对上次读入或保存的 `original` | 标签关闭钮变成 7px 灰点；悬停才变回 X。标签 title 写明「有未保存的修改，相对上次打开或保存，不是 Git 状态」 |
| Git 色条 | 缓冲区相对 **Git 暂存区**（`git show :./路径`），不是相对 HEAD，也不是相对上次保存 | 行号槽左侧 3px 色条 |
| 智能体 inline diff | 这一轮智能体改动的 chunk，可接受/撤销 | 行内覆盖层，和 Git 色条同时存在 |

### 5.1 标签

- 单击切换。未钉住的是预览标签（斜体一类的 `is-preview`），再开另一个未钉住文件会替换它。双击或保存后钉住。
- 一改内容就自动钉住。
- 中键或 X 关闭。脏标签关闭前会问。
- 右键：关闭、关闭其他、关闭右侧、全部关闭等（脏标签不能被「关闭未修改」扫掉）。
- 滚轮横滚标签。⌘/Ctrl+W 或 F4 关当前标签。
- 标签脏 **不等于** Git 有改动。保存后脏点消失，Git 字母和色条还在，直到提交或撤回。

### 5.2 Git 色条

`EditorWithDiff` 挂一个 `GitGutter`。基准：

- 不在 Git 仓库里，或文件是二进制：不画。
- 暂存区没有这份文件（未跟踪）：基准当成空字符串，所以整份新文件的每一行都是新增绿条。
- 有暂存内容：和暂存区全文做行 diff。

因此：**只暂存、缓冲区已经和暂存区一致时，色条消失**，即使相对上次提交仍有改动。文件树和 Git 页的「暂存的更改」仍会列出它。色条表示的是「编辑器里还有没进暂存区的行」。

色条种类：

| 种类 | 样子 |
|---|---|
| 新增 | 绿色竖条 |
| 修改 | 黄色虚线竖条 |
| 删除 | 红色三角，指向被删行的位置。删在文件末尾时三角贴在最后一行下沿 |

输入时 120ms 后重画，不重新请求 Git。`gitEpoch` 变化（状态刷新）才重新拉暂存区基准。

色条不能点击暂存或撤回。悬停说明是「相对暂存区新增/修改/删除的行，还没有暂存」。没有 Git blame，没有行内「撤销这一行」。

### 5.3 从 Git 页打开变更

`openSourceControlChange` 不再打开普通编辑标签。它按组读取两侧文本，新建或复用一个钉住的只读 diff 标签（`GitDiffEditor`）。同一文件的普通标签可以同时还在。diff 标签没有脏点，⌘/Ctrl+S 不会把它写回磁盘。

从文件树打开仍走 `openEditorFile`：不脏就重读磁盘，脏则只激活已有缓冲。

从 `< 序号/总数 >` 打开，或打开的是缺失文件时，会切到「文件」页并展开到所在目录。目录还在磁盘上时，缺失文件作为红色幽灵节点挂在该目录下，行右侧字母是 `D`。普通打开已存在的文件不会自动展开树。Accept 全部会清掉这条待处理记录，字母和 `< 序号/总数 >` 一起消失。

### 5.4 保存

⌘/Ctrl+S 保存当前文件。设置里格式化开启时先格式化再写。`writeWorkspaceFile` 成功后，这个标签的 `original` 更新成缓冲区，脏点消失，然后同时 `refreshGitStatuses()` 和 `sourceControlPanel.refresh()`。

保存不自动暂存。

### 5.5 磁盘被别人改了

智能体写文件，或 diff store 的 `diskEpoch` 变化时，会重读文件树、重拉两份 Git 状态。

当前标签 **脏**，且磁盘内容和缓冲区不同：不改缓冲区。智能体改动的提示是「文件已被智能体修改，当前未保存内容尚未覆盖。」Git 撤回或同步的提示是「磁盘上的文件已变化，当前未保存内容尚未覆盖。」两个按钮：

- 「保留当前内容」：只关掉这行，不读磁盘。
- 「加载磁盘版本」：强制重读，缓冲区换成磁盘，脏状态清除。

当前标签不脏：直接换成磁盘内容。

智能体一次 Edit/Write 结束（tool_result）时，还会尝试打开被改的那个文件。标签不脏就换成磁盘内容。标签是脏的，且磁盘内容和缓冲区不同，不覆盖，出提示条「文件已被智能体修改，当前未保存内容尚未覆盖。」可选保留当前内容或加载磁盘版本。运行变成 completed / failed / stopped 时同样：不脏就重读，脏且磁盘不同才出同一条提示，不强制覆盖。

### 5.6 点 Git 之前会先保存

见第 1 节。切到 Git 时若有脏标签，先确认再保存。取消则不切换、不写盘。确认后写完再拉状态，所以 Git 页能看到刚刚编辑器里的字。写盘失败则 Git 页不刷新，编辑器 `error` 显示错误。

切回「文件」或「大纲」不会反向刷新 Git，也不会撤回这次自动保存。

### 5.7 标签栏上的当前文件全部接受 / 撤销

有待处理的智能体 diff 时，编辑器标签栏右侧是 `< 序号/总数 >`，用来在这些文件之间切换。当前文件里有 Accept/Undo 时，旁边还有 `上 序号/总数 下`，点一下把对应差异滚到编辑区中间。再右边两个按钮只作用于**当前打开的文件**：

| 按钮 | 结果 |
|---|---|
| Accept 全部 | 按当前编辑器里已经显示的 Accept，逐个接受。不改磁盘。文件已不在磁盘上、又没有行内差异时，接受这次缺失，把它移出 `< 序号/总数 >` |
| Undo 全部 | 按当前编辑器里已经显示的 Undo，从文件末尾往前撤销。不碰其他文件 |

没有行内差异、当前文件也不是缺失文件，或这个工作区正有智能体在跑时，Accept 全部不可用。Undo 全部只在有行内差异时可用。

## 6. 状态什么时候会一起变

工作台自己持有一份 `gitRepositories`（文件树字母、分支副标题）。Git 页再持有一份 `repositories`。Git 页刷新成功会 `emit("updated")`，工作台用这份结果 **整份替换** 自己的列表，并 `gitEpoch += 1`（编辑器色条重拉基准）。

两边都会调用同一个 `listProjectGitStatus`。后返回的那次覆盖先返回的。Git 页还会按当前 `workspaces` id 滤一遍；工作台自己的刷新不过滤。

| 时机 | 文件树字母 | Git 页列表 | 编辑器色条基准 | 编辑器正文 |
|---|---|---|---|---|
| 工作区列表变化 | 刷新 | 面板 watch 工作区 id 也会刷新 | 跟着 epoch | 否 |
| 保存文件 | 刷新 | 刷新 | 刷新 | 已是刚写入的内容 |
| 切到 Git tab | 刷新 | 刷新 | 刷新 | 有脏标签时先确认，确认后才全部保存 |
| 重命名、删除 | 刷新 | 刷新 | 刷新 | 标签路径改掉或关掉 |
| 新建文件 | 刷新 | 刷新 | 刷新 | 打开新文件 |
| 资源管理器「刷新」 | 刷新 | 刷新 | 刷新 | 否 |
| 暂存 / 提交 / fetch | 用面板回传的列表替换 | 刷新 | 刷新 | 不重读（这些操作不改工作区文件字节） |
| 撤回 / 同步 / 提交并同步 / 中止合并 | 用面板回传的列表替换 | 刷新 | 刷新 | 不脏的已打开文件换成磁盘；脏的出提示，不覆盖 |
| 智能体写入 tool_result | 刷新 | 刷新 | 刷新 | 尝试强制打开被改文件 |
| 运行结束 | 刷新 | 刷新 | 刷新 | 不脏就重读；脏则只提示 |

## 7. 点哪里一览

### 左栏 tab

| 点 / 按 | 结果 |
|---|---|
| 文件 | 显示文件树。不保存 |
| Git | 有未保存文件时先确认。确认后保存并刷新；取消则留在原 tab。按钮上的数字是变更文件数 |
| 大纲 | 当前文件符号。点符号，编辑器滚到该行并选中 |
| 标签条滚轮 | 横向滚动 |
| 左右箭头 | 仅溢出时出现，切到相邻 tab |

### Git 页

| 点 / 按 | 结果 |
|---|---|
| 仓库头（多个工作区） | 折叠/展开 |
| 分支名 | 切换已有分支，或新建分支 |
| 更多操作 | 刷新、拉取、推送、获取 |
| ahead/behind 数字或主按钮「同步更改」 | pull 再 push |

| chevron | 仅主按钮是提交时出现：提交 / 提交并推送 / 提交并同步 |
| 上/下方向键 | 在提交说明的开头或末尾翻最近用过的说明 |
| 火花 | 用暂存 diff 生成说明 |
| 顶栏刷新、列表/树 | 重新拉状态；在列表和目录树之间切换 |
| 中止合并 | `merge --abort` |
| 点变更文件一行 | 打开只读 diff 标签 |

| 暂存组减号 / 右键取消暂存 | 取消暂存 |
| 其他组加号 / 右键暂存 | 暂存选中的路径，不是 `git add -A` |
| 撤回 | 确认后 restore 或删除未跟踪文件 |
| 组头加号或减号 | 只处理这一组里的路径 |

### 文件树

| 点 / 按 | 结果 |
|---|---|
| 单击文件 | 打开。脏则不重读 |
| 双击文件 | 打开并钉住 |
| 行尾字母或目录圆点 | 只表示状态，不能点 |
| 右键 | 打开、新建、重命名、删除、复制路径、在访达显示、添加到聊天。Git 工作区头可以复制分支名。没有暂存或撤回 |
| F2 / Delete | 重命名 / 删除 |
| 拖拽 | 加进聊天 |

### 编辑器

| 看到 / 点 | 含义 |
|---|---|
| 标签灰点 | 相对上次打开或保存有未写入磁盘的字。悬停变 X。title 写明这不是 Git 状态 |
| 绿/黄/红行号槽 | 相对暂存区的未暂存行。悬停写明「还没有暂存」。不是相对上次提交 |

| 标签栏 `< 序号/总数 >` | 在还有智能体 diff 的文件之间切换 |
| Accept 全部 / Undo 全部 | 只处理当前打开的文件。缺失且没有行内差异时，Accept 全部接受这次缺失并移出导航 |

## 8. 审阅时建议对着代码看的事实

下面是实现和界面容易对不上的地方。请判断哪些是 bug、哪些是体验问题、哪些可以保持。

1. **源码管理只服务 Worktree。** 「当前分支」药丸和「提交会写回原仓库」的警告在界面上有，但状态接口和写操作都拒绝非 worktree。这类 Git 仓库在 Git 页展开后是空的，文件树也没有字母。编辑器色条却可能仍然出现。
2. **打开 Git tab 会在确认后保存全部脏文件。** 取消则不切换。确认之后不能按文件挑选。保存失败则 Git 页不刷新。
3. **撤回、拉取、同步、切换分支、中止合并会重读不脏的已打开文件；脏的只出提示。** Git diff 标签不参与这次重读。暂存和普通提交不改工作区字节，所以不重读。脏标签如果选择「保留当前内容」再保存，仍会把缓冲区写回磁盘。
4. **色条比的是暂存区，列表比的是 HEAD 和工作区。** 悬停已说明色条相对暂存区。暂存之后色条可以全没了，Git 页「暂存的更改」还在。未跟踪文件色条把整文件当新增。
5. **同一文件能同时出现在「暂存的更改」和「更改」。** 撤回只动工作区，暂存还在。已跟踪文件的确认文案仍不提暂存区。
6. **未跟踪目录的撤回是 `git clean -fd`，只针对该目录。** 确认框写明会删掉目录内全部未跟踪文件。单个未跟踪文件用 `git clean -f`，不会连带别的目录。
7. **「发布分支」在有暂存但没写说明时，先确认再 push。** 成功后提示暂存仍在本地。取消则不推送。
8. **分支可以切换，也可以新建。** 合并另一个分支、变基、stash 仍然没有界面。`gitMergeWorkspaceBranch` 和 `gitCommitMultiple` 还没接到按钮上。
9. **新建文件和资源管理器「刷新」会拉 Git 状态。** 重命名、删除也会同时刷新 Git 页。
10. **Git 操作仍然全局互斥。** 被挡住的按钮 title 会说明有别的 Git 操作在进行。不能按仓库并行。
11. **文件树不能暂存或撤回。** 字母和圆点不可点，右键没有暂存或撤回。Git 工作区头可以复制分支名。目录圆点的 title 会写「目录下有 N 处改动」。
12. **从 Git 打开的是只读 diff 标签，不定位到改动行，也不在树里展开。** 普通文件标签不受这次打开影响。删除的文件在 diff 里表现为一侧空白。
13. **智能体改到已打开且未保存的文件时，不再覆盖缓冲区。** 和运行结束一样，只出提示条。不脏的标签仍会换成磁盘内容。
14. **标签脏点、Git 字母、色条、智能体 diff 四套「这里改过」同时存在**，颜色也不统一（脏点是灰的，Git 修改是黄的）。标签 title 和色条悬停已经写了各自相对什么。

## 9. 不在这套 UI 里的能力

审阅「缺什么」时可以当清单：

- 合并另一个分支、变基、储藏 stash
- 按行 / 按 hunk 暂存
- 文件树右键里的暂存 / 撤回
- 色条点击暂存或还原该行
- 多仓库一次提交（`gitCommitMultiple` 未接入界面）
- 提交图的 incoming/outgoing 节点、引用过滤、分页以外的分支树
- 约定式提交模板。提交前钩子失败时仍是面板上的横幅，可以补运行时或本次跳过
