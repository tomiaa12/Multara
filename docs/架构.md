# Multara 架构说明

Multara 是本地优先的多智能体开发工作区。桌面壳是 Tauri 2，界面是 Vue 3 + TypeScript + Pinia，领域逻辑和系统能力在 Rust + SQLite。智能体不通过 Multara 自己的 HTTP API 改文件，而是 spawn 本机 AI CLI（如 `cursor-agent`、`claude`），在隔离工作区目录里直接读写磁盘。Multara 负责调度、持久化、流式解析和 UI 展示。

---

## 1. 整体架构

### 1.1 技术栈

| 层 | 技术 |
|---|---|
| 桌面壳 | Tauri 2（`@tauri-apps/api` v2） |
| 前端 | Vue 3.5、Pinia 4、Vue Router 5、Vite 8、TypeScript 5.9 |
| 编辑器 | Monaco Editor（`@guolao/vue-monaco-editor`） |
| Markdown | `marked` + `DOMPurify` + `highlight.js` + `mermaid` |
| 后端 | Rust 2021、rusqlite（bundled SQLite） |
| 智能体进程 | 本机 CLI：`claude`、`cursor-agent`、`codex`、`gemini`、`qwen` 等 |

### 1.2 分层

```
┌─────────────────────────────────────────────────────────┐
│  Vue UI（views / components）                            │
│    ↕ Pinia store（src/stores/app.ts）                    │
│    ↕ services/backend.ts（invoke / 浏览器 preview mock） │
├─────────────────────────────────────────────────────────┤
│  Tauri Commands（src-tauri/src/commands.rs）             │
│    → database.rs     SQLite 读写                         │
│    → executor.rs     运行队列 + spawn CLI + 流式解析     │
│    → files.rs        工作区文件树 / 读写                  │
│    → workspace.rs    隔离目录（worktree / copy / direct） │
│    → session.rs      会话-工作区绑定、项目锁              │
│    → runtime.rs      检测本机 CLI                         │
│    → git.rs          源码管理                             │
│    → resources.rs    Skills / MCP 扫描                    │
├─────────────────────────────────────────────────────────┤
│  本机文件系统 + 本机 AI CLI 子进程                        │
└─────────────────────────────────────────────────────────┘
```

浏览器预览（`pnpm dev`，无 Tauri）走 `backend.ts` 的 mock，不能读写本机文件。真正改文件、跑智能体必须在 `pnpm tauri:dev` 里。

### 1.3 目录

```
src/                          前端
  App.vue                     全局壳：侧栏 + RouterView + 浮动聊天
  router.ts                   路由
  domain/types.ts             全量 TS 领域类型
  services/backend.ts         Tauri invoke 封装
  stores/app.ts               核心状态：聊天、智能体、工作区、运行态
  components/
    WorkspaceWorkbench.vue    三栏工作台
    ChatPanel.vue             聊天面板
    ChatMessageItem.vue       按 role 分流用户/助手消息
    chat/                     回答渲染子组件
    workbench/                Monaco、未保存、Git 状态
    dashboard/                需求列表
  views/                      页面
src-tauri/src/
  main.rs                     注册全部 command
  commands.rs                 invoke 入口
  executor.rs                 智能体执行与流解析
  workspace.rs / files.rs / git.rs / session.rs / runtime.rs
```

### 1.4 启动

```
App.vue onMounted
  → store.initialize()
    → backend.bootstrap()          invoke("bootstrap")
      → SQLite 全量：projects / workspaces / agents / squads / sessions / ...
      → runtime::detect()          扫描本机 CLI
      → resource_manager::scan()   扫描 Skills / MCP
    → registerRunEvents()          listen("run-event")
    → loadMessages(activeSessionId)
```

SQLite 路径：`{app_data_dir}/multara.sqlite3`。

## 2. 工作区怎么展示

工作区（`Workspace`）是挂在某个需求（`Project`）下的一个可读写目录。一个需求可以有多个工作区（多个 Git 仓库或文件夹）。

### 2.1 数据模型

```ts
interface Workspace {
  id: string
  projectId: string
  sessionId?: string | null          // 会话专属副本；主流程多为 null
  name: string
  kind: "git" | "folder"
  sourcePath: string                 // 用户选择的原目录
  workPath: string                   // 智能体实际 cwd / 文件树根
  branch: string | null
  isolationMode: "worktree" | "copy" | "direct"
}
```

添加工作区：需求页 `AddWorkspaceModal` → `store.queueAddWorkspaces()` → `backend.addWorkspace()` → Rust `workspace::prepare()`。

### 2.2 三种隔离模式

`workspace.rs::prepare()` 根据用户选择的 `isolated | direct` 和目录是否为 Git 仓库决定：

| 用户选择 | 目录类型 | `isolationMode` | `workPath` | 含义 |
|---|---|---|---|---|
| 直接打开 | 任意 | `direct` | 原目录 | 改真实目录 / 当前分支 |
| 隔离 | Git 仓库 | `worktree` | `{app_data}/workspaces/{projectId}/{id}` | `git worktree` 独立检出，默认分支 `multara/{project短id}/{workspace短id}` |
| 隔离 | 普通文件夹 | `copy` | 同上 | 整目录复制一份 |

文件树标题右侧的 pill 由 `workbench/workspace-mode.ts` 计算：

- Git + worktree → **Worktree**，副标题 `{branch} · 独立工作树`
- Git + direct → **当前分支**，副标题 `{branch} · 正在改真实分支`
- 非 Git + copy → **非 Git**，副标题 `普通文件夹 · 隔离副本`
- 非 Git + direct → **非 Git**，副标题 `普通文件夹 · 原目录`

### 2.3 三栏工作台

进入 `/projects/:projectId` 后，`ProjectWorkspaceView` 只传 `projectId`，真正布局在 `WorkspaceWorkbench.vue`：

```
.workbench
├── aside.workspace-sidebar     左：文件树 / Git
├── .panel-resize-handle        可拖
├── section.editor-area         中：标签 + Monaco
├── .panel-resize-handle        可拖
└── aside.project-chat          右：ChatPanel（compact）
```

左右栏宽度存在本地，范围约 160–440（左）和 ≥240（右），中间编辑区至少 160。

当前展示哪些工作区：

```ts
workspaces = store.data.workspaces
  .filter(w => w.projectId === projectId)
  // 若当前会话有专属 workspace，只用专属的；否则用项目级共享 workspace
  .filter(w => w.sessionId === activeSessionId || !w.sessionId)
```

### 2.4 左栏：文件树

1. 每个 workspace 一行头：图标、名称、隔离模式 pill、刷新 / 折叠。
2. 展开后懒加载根目录：`loadWorkspaceRoot(id)` → `backend.listWorkspaceDirectory(id)` → Rust `files` 读 `work_path`。
3. 点文件夹再调 `listWorkspaceDirectory(id, prefix)`，结果缓存在 `directoryChildren`。
4. 可见行由 `visibleTree()` 按 `expandedDirectories` 拼出，缩进 `18 + depth * 14`。
5. Git 状态 badge 来自 `refreshGitStatuses()` + `tree-git-status.ts`（M / A / D 等）。
6. 右键：新建、重命名、删除、复制路径；Git 工作区头还可以复制分支名。可拖到右侧输入框作为文件引用。

左栏第二个 tab 是 `SourceControlPanel`：`list_project_git_status`、暂存、提交、拉取、推送。

### 2.5 中栏：编辑器

- 单击文件：预览标签（未 pinned），`openEditorFile()` → `backend.readWorkspaceFile()` → Monaco `setValue`。
- 双击：钉住标签。
- 保存：`Ctrl/⌘+S` 或工具栏 → `backend.writeWorkspaceFile()`。这是**用户手动写盘**，和智能体改文件不是一条路。
- dirty 检测：`activeFile.content !== originalContent`，离开工作台会走 `unsaved-editor.ts` 确认。
- 智能体改了当前打开的文件、且本地有未保存内容时，顶部出现条：「文件已被智能体修改，当前未保存内容尚未覆盖」，可选保留或加载磁盘版本。

### 2.6 打开文件数据流

```
点击树节点 onTreeOpen
  → openFile(workspaceId, entry)
    → openEditorFile(path)
      → invoke("read_workspace_file")
      → 创建 / 复用 EditorTab
      → Monaco setValue
      → 记录 originalContent 做 dirty
```

聊天里的 diff 卡片点文件名：

```
FileDiffCard.openFile
  → store.revealWorkspaceFile(path, startLine, endLine)
  → WorkspaceWorkbench watch fileReveal
  → 在各 workspace 中匹配路径并 openFileAt（跳转行）
```

## 3. 智能体怎么加载

智能体是 SQLite 里的配置记录，不是远程账号。真正执行时，用它绑定的**本机 CLI 运行时**在工作区目录里跑。

### 3.1 配置存在哪

表：

- `agents`：名称、头像、说明、`instructions`（用户备注）、`runtime_id`、`model`、并发、`system_key`
- `agent_resources`：绑定的用户 skill / mcp id（内置 `multara-*` skill 不进这张表）
- `runtime_settings` / `custom_runtimes`：并发与自定义 CLI
- `squads` / `squad_members`：小队与队长（不预置）

首次启动 `database.rs` 会 seed **Miku**（`id=miku`，`system_key=miku`）和对着 Miku 的欢迎会话。产品身份说明嵌在二进制里，`instructions` 列只放用户 notes。不预置阿库、小审或产品开发小队。软件更新不会删 sqlite。

智能体跑任务时，子进程 PATH 上有 `multara` CLI（sidecar `multara-cli` 的 shim），平台对象走 CLI。内置 skill 写在应用数据目录 `builtin-skills/`，不进项目仓库。

### 3.2 启动时如何进内存

```
bootstrap()
  → list_agents(db)          JOIN agent_resources → skillIds / mcpIds
  → list_squads(db)
  → runtimes(db)             runtime::detect() + DB 并发设置
  → resource_manager::scan() 扫 ~/.cursor/skills 等
```

前端：`store.data.agents` / `squads` / `runtimes`。配置页 `AgentDetailView` 改完走 `store.saveAgent()` → `save_agent`（校验 runtime 必须 online，UPSERT `agents` 并重写 `agent_resources`）。

### 3.3 运行时检测

`runtime.rs::RUNTIME_SPECS` 预定义：

| id | 显示名 | 可执行文件 |
|---|---|---|
| claude | Claude Code | `claude` |
| cursor | Cursor | `cursor-agent` / `agent` |
| codex | Codex | `codex` |
| copilot | GitHub Copilot | `github-copilot-cli` / `copilot` |
| opencode | OpenCode | `opencode` |
| gemini | Gemini CLI | `gemini` |
| qwen | Qwen Code | `qwen` |
| kimi | Kimi CLI | `kimi` |

`which::which()` 找到则为 `online`，否则 `not_found`。`save_agent` 拒绝绑定离线运行时。

Cursor 执行参数大致是 `-p --output-format stream-json --yolo`，并加 `--workspace`、`--add-dir`、`--model`。

### 3.4 会话如何选中智能体

绑定在会话上，不是全局单选：

```ts
interface ChatSession {
  targetType: "agent" | "squad"
  targetId: string
  projectId: string | null
}
```

`ChatPanel` 顶部选择器：

```
options = agents.map(a => "agent:" + a.id)
        + squads.map(s => "squad:" + s.id)

targetValue 读写 session.targetType:targetId
  → store.setSessionTarget()
    → UPDATE chat_sessions
```

新建会话默认第一个 agent，没有 agent 则第一个 squad。

发送时 `commands.rs::dispatch()`：

- `target_type == "agent"`：为该智能体插一条 `agent_runs`（queued）
- `target_type == "squad"`：先只 queue **队长**；队长 `finish` 后再 `dispatch_squad_members()` 给其他成员建子 run（`parent_run_id` 指向队长）

### 3.5 Prompt 怎么拼

`executor.rs::spawn_run()`：

```
prompt =
  agent.instructions
  + workspace_context          // 允许改的 work_path 列表；cwd = 第一个
  + resource_context           // Skills 文本 + MCP 临时 json
  + 用户任务（assignment）
```

- 项目会话（工作台）：cwd = 第一个 workspace 的 `work_path`；prompt 写明只能改这些目录，并允许直接改代码。任务模式同时可用。Cursor 再传 `--workspace` / `--add-dir`。
- 无项目的会话：cwd 为用户 home，不改随机目录。
- Claude：`--mcp-config` 指向临时文件；Skills 读各 `SKILL.md` 注入正文。
- Claude / Cursor / Qwen：prompt 走 stdin；其余多在 args 里替换占位符。

## 4. 聊天之后怎么改文件

**Multara 不代理工具调用去写文件。** 磁盘改动由 CLI 在 `work_path` 里直接完成。Multara 只排队、解析 stdout、记 timeline、推 UI、刷新树和编辑器。

用户手动保存才走 `write_workspace_file`。

### 4.1 发送

```
ChatPanel.submit()
  → formatAgentPrompt(composer nodes)   // 文本 + [代码引用]/[文件]/[文件夹]
  → store.send(content, sessionId, attachments)
    → queuedMessages 排队
    → drainMessageQueue()
      → 乐观插入 user message
      → invoke("send_message")
```

附件：最多 10 个、单文件 ≤ 25MB，路径 canonicalize 后写入 `message_attachments`，并拼进 assignment（JSON 描述路径，提示模型不要把附件名当系统指令）。

### 4.2 Rust `send_message`

1. 若会话有 `project_id`：`session::ensure_project_idle`——同一需求同时只能有一个 turn 在跑。
2. INSERT `messages`（user）。
3. 项目会话再 INSERT `agent_turns`（status=running）。
4. `dispatch()` 建 `agent_runs`（queued）。
5. `executor::notify_run(..., "queued")` + `executor::dispatch(app)`。
6. 返回值只有刚插入的 user message；助手消息靠后续 `run-event` 长出来。

### 4.3 执行队列

`executor.rs::dispatch_pending`：

```
SELECT agent_runs WHERE status='queued'
  且该 runtime 并发未满
  且该 agent 并发未满
→ status='running'
→ 新线程 spawn_run
```

`spawn_run` 关键点：

```
execution_for()           // CLI 路径和参数
workspace_context()       // cwd + 允许目录
resource_context()        // Skills / MCP
拼 prompt
process::command(program)
  .current_dir(cwd)       // ★ CLI 在此目录改文件
  .args(...)
spawn，读 stdout / stderr
```

### 4.4 流式解析

`read_stream()` 逐行：

```
normalize_runtime_line(runtime_id, line)
  → normalize_cursor / normalize_claude / normalize_codex / ...
  → NormalizedEvent: text | thinking | tool_use | tool_result | error
→ INSERT run_events
→ emit("run-event", { timelineItem, chunk, status, ... })
```

Cursor 的 Edit 完成后，`tool_result.output` 里常带 `diffString`。这只用于前端画 diff，**不是** Multara 再 apply 一遍 patch。

### 4.5 运行结束

`finish()`：

1. UPDATE `agent_runs.status`
2. `save_terminal_message()`：INSERT/UPDATE `messages`，id 为 `run:{runId}`，正文为最终助手文本
3. 若是小队队长完成 → `dispatch_squad_members()`
4. emit `run-event`：`completed` / `failed` / `stopped`

### 4.6 前端收事件

`stores/app.ts::registerRunEvents()`：

```
listen("run-event")
  → runStates[runId] = payload
  → 找到或创建 live 消息 id="run:{runId}"
  → 合并 timelineItem（按 seq upsert）
  → chunk 追加到 message.content（completed 时用最终 chunk 覆盖）
  → 结束态：listChatMessages 与 DB 对齐，保留仍在 queued/running 的 live 消息
```

小队队员的消息会标 `audienceType: "agent"`，聊天里显示为内部 `@队员`。

### 4.7 工作台如何感知磁盘变化

`WorkspaceWorkbench` 盯 `store.runStates`：

| 条件 | 动作 |
|---|---|
| 本项目会话、running、且 `tool_result` 的 tool 是 `Edit` 或 `Write` | 刷新文件树、Git、源码面板；打开或刷新被改文件；立刻重算 Monaco inline diff（Accept/Undo） |
| 本项目会话 run 变为 completed / failed / stopped | 上面全部 + 再对齐一次 `refreshActiveFile()` / `loadSession` |

`refreshActiveFile()`：重新 `readWorkspaceFile`。若当前标签 dirty，不覆盖，只提示「文件已被智能体修改」。

### 4.8 全链路

```
用户 Enter
  → send_message（SQLite: messages + agent_runs）
  → executor 排队
  → spawn cursor-agent / claude，cwd = work_path
       ↓ CLI 自己 Edit / Write / Bash
       ↓ 操作系统写磁盘
  ← stdout stream-json
  → normalize → run_events + emit run-event
  → Pinia messages[].timeline
  → ProcessFold / FileDiffCard
  → 工作台刷新树和当前文件
```

Diff 卡片**不写盘**。点文件名只是 `revealWorkspaceFile` 打开 Monaco。

## 5. 回答怎么展示

### 5.1 组件树

```
ChatPanel
  ├── 会话标签（项目内多会话，localStorage 见 chat-open-tabs.ts）
  ├── 消息列表
  │     ChatMessageItem
  │       ├── UserPrompt            用户气泡、附件、当时选的执行者
  │       └── AssistantMessage
  │             ├── 头像 / 名称 / 角色 pill（队长、队员、失败）
  │             ├── ProcessFold     过程：思考、探索、diff、终端
  │             ├── FailureBubble   失败
  │             ├── RichContent     最终 Markdown
  │             └── MessageFooter   时间；无 timeline 时显示耗时
  └── ChatComposer                  输入、引用芯片、附件、发送 / 停止
```

`messageRunning(message)`：该消息的 `runId` 在 `runStates` 里仍是 `running`。

### 5.2 流式正文

`AssistantMessage`：

```ts
liveText = timeline 里 eventType === "text" 的 content 拼起来
rawContent = message.content || liveText
```

运行中：`run-event.chunk` 不断写进 `message.content`，同时 timeline 也堆 `text` 事件。结束后以 DB 里的终态 content 为准。

小队队长的 assignment 类消息会用 `assignmentVisibleText()` 裁掉内部派活说明，只给用户看该看的部分。

### 5.3 Markdown / 代码

`RichContent.vue`：

1. `marked.parse`（GFM + 换行）
2. `DOMPurify.sanitize`
3. `highlight.js` 高亮（`vue`/`tsx` 等会别名到 xml/typescript）
4. 代码块外包一层，带「复制」
5. `language-mermaid` 动态渲染图
6. `language-html-preview` 内联 HTML 预览
7. 表格外包滚动容器

### 5.4 过程折叠（timeline）

原始事件：

```ts
interface TimelineItem {
  seq: number
  eventType: "text" | "thinking" | "tool_use" | "tool_result" | "error"
  callId, tool, content, input, output
}
```

`timeline-display.ts::groupTimeline()` 先合并碎片 `tool_use`，再按 `callId` 配对 `tool_result`，最后分类：

| block | 组件 | 来源 |
|---|---|---|
| thinking | `ThinkingLine` | `eventType === "thinking"` |
| explore | `ExploreGroup` | Read / Grep / Glob / Browser 等，相邻的会并成一组 |
| edit | `FileDiffCard` | Edit / Write |
| shell | `ShellCard` | Bash / 终端 |
| tool | `ToolCallRow` | 其余工具 |

`text` 不进过程条，进最终正文。`error` 进失败气泡。

运行中：`ProcessFold` 展开，边到边出卡片。结束后收成 `<details>`，摘要类似「工作了 12 秒」（`workFoldLabel`）。

思考文案：`thinkingSummary()` —— 运行中「思考中…」；短内容「简要思考」；长内容「思考过程」。

### 5.5 Diff 卡片

`FileDiffCard` 用 `editDiff()`，优先级：

1. `tool_use.input` 的 `old_string` / `new_string` → 前端 LCS 行 diff
2. input 里的 unified patch
3. `tool_result.output` 的 JSON `diffString`（Cursor）或纯 unified diff
4. Write 且只有新文件内容 → 整份当新增行

超过 4 行默认折叠。点文件名跳转编辑器。解析不出 diff 时显示「已写入工作区」。

### 5.6 小队内部消息

`message-speaker.ts::speakerForMessage()`：

- 队长对用户：正常助手气泡
- 队员（`audienceType === "agent"`）：`assistant-turn.internal`，并显示 `@队员名`

## 7. 补充

1. **没有 Multara 云 API。** 智能体 = 本机 CLI + 本地 SQLite 配置。
2. **同一需求同时只能跑一个 turn**（`ensure_project_idle`）。
3. **`src/features/code-review/`** 有独立 DiffEngine，目前未接到工作台；审查相关表已在迁移里删掉。
4. **`workspaces.session_id` + `session_workspaces`** 支持会话级隔离副本，主路径仍是项目级共享 workspace。
5. 浏览器 `/preview` 只用 `preview-workspace.ts` / `preview-messages.ts` 的假数据，用来调样式。
