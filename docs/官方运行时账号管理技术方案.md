# 官方运行时账号管理技术方案

范围：Multara「运行时」页里的**内置运行时**（`kind = builtin`，即 `shared/cli-catalog.json` 里的官方 CLI），支持查看当前登录的账号，并在多个账号之间切换。**自定义运行时和中转站不在范围内**（它们用任务级 Key，不碰 CLI 的全局登录）。

参考实现：`cc-switch` 授权中心（`src/components/settings/AuthCenterPanel.tsx`、`src-tauri/src/services/agy_account/`、`src-tauri/src/services/kimi_oauth/`、`src-tauri/src/proxy/providers/*_auth.rs`、`src-tauri/src/services/provider/codex_login.rs`）。

## 0. 结论

1. **能做，但做法是「备份当前登录 → 存进 Multara 的账号库 → 切换时写回」**，而不是给每个厂商重写一遍 OAuth。CLI 自己负责登录，Multara 只负责收录和换回。
2. 切换改的是**该 CLI 的全局登录**：终端里、IDE 里用同一个 CLI 也会跟着变。正在跑的进程不会换号。
3. 能支持到什么程度，取决于这个 CLI 把登录存在哪：

| 档 | 运行时 | 看当前账号 | 切换 |
|---|---|---|---|
| A | codex、kimi、antigravity、cursor、grok | 能显示邮箱或用户名 | 支持（写回文件或钥匙串） |
| B | claude、gemini、qwen、copilot | 能显示登录方式，部分能显示邮箱 | 支持，但要先在本机实测确认凭据位置 |
| C | opencode、pi、openclaw、hermes、mcode、deveco | 只能显示默认供应商/模型 | 支持「整份配置快照」切换（等于换 Key/供应商） |
| D | codebuddy、codearts、qoder、qoderclicn、traecli、kiro、reasonix、dim、dsh、zeroclaw、omp、qwenpaw | 只能显示「已登录 / 未登录 / 未知」 | 暂不支持，只给「去终端登录」 |

D 档的凭据格式不公开或无法确认，强行备份写回容易把 CLI 弄坏，第一期不做切换；后续确认某个 CLI 的凭据位置后，在注册表里加一条就能升到 A/C 档（见第 3 节）。

## 1. CC Switch 是怎么做的

CC Switch 授权中心管 5 类账号，分两种用法：

| 账号 | 存在哪 | 怎么用 |
|---|---|---|
| GitHub Copilot | `~/.cc-switch/copilot_auth.json`（多账号 + `default_account_id`） | 设备码登录；**由本地路由注入 token**，不改 Copilot CLI 自己的登录 |
| ChatGPT（`codex_oauth`） | `~/.cc-switch/codex_oauth_auth.json` | 设备码登录；路由注入，另可把完整 token 写进 `~/.codex/auth.json` 做「官方登录绑定」 |
| xAI | `~/.cc-switch/xai_oauth_auth.json` | 路由注入 |
| Kimi Code | `~/.kimi-code/credentials/kimi-code*.json` + 自己的 `kimi_accounts.json`（只存身份标签） | **直接切 Kimi Code 的默认账号**（`use_account`） |
| Antigravity（agy） | 钥匙串 service `gemini` / account `antigravity` + 自己的 `agy_accounts.json` | **整条写回钥匙串**，agy 下次启动就是新账号 |

对 Multara 有用的是后两种（Kimi、agy）的思路，也就是**直接改 CLI 的本机登录**。前三种依赖 CC Switch 的本地路由来注入 token，Multara 的内置运行时不走路由，不适用。

值得照搬的规矩（摘自 `agy_account/mod.rs`、`codex_login.rs`、`kimi_oauth/lock.rs`）：

- **切换前先把当前登录收回来**：是已收录的账号就用最新内容更新它（CLI 可能已经刷新过 token），不认识的就自动收录成新账号，切走也不会丢。
- **账号按稳定身份区分**：id_token 的 `sub`、用户 id，而不是显示名或邮箱前缀。
- **从列表删除只删 Multara 的副本**，不替 CLI 登出。
- **不自动换号**：额度用完、请求报错都不切，只由用户触发。
- **写文件用原子写 + 0600**（`atomic_write_private`），账号库不参与云同步。
- **和 CLI 抢同一把锁**：Kimi 刷新 token 时会锁 `{home}/oauth/<name>.lock`，写凭据前先拿同一把锁，避免覆盖 CLI 刚轮换的 refresh token。
- **钥匙串通过 `/usr/bin/security` 读写**：agy 用的 go-keyring 在 macOS 上也是调这个程序，条目的访问控制信任它，所以不会弹授权框。
- 认不出格式的登录**整条暂存**（`agy-login-stash.json`），不丢弃。

## 2. 各运行时的登录存在哪

以下是本机和 CC Switch 代码核对后的结果。「身份字段」用来显示当前账号，也用来判断当前登录是不是已收录的某个账号。

### A 档

| 运行时 | 凭据位置 | 身份字段 | 备注 |
|---|---|---|---|
| codex | `~/.codex/auth.json`；`config.toml` 里 `cli_auth_credentials_store = "keyring"` 时在钥匙串 | `tokens.id_token` 的 `email`、`sub`；`tokens.account_id` | keyring 模式第一期只显示状态不切换。参考 `codex_login.rs` |
| kimi | `~/.kimi-code/credentials/kimi-code.json`（根目录可被 `KIMI_CODE_HOME` 改） | 凭据里的用户 id；昵称需调 `/me` | 写之前拿 `{home}/oauth/kimi-code.lock`。参考 `kimi_oauth/` |
| antigravity | 钥匙串 service `gemini`、account `antigravity`，值是 `go-keyring-base64:` + base64 JSON | `id_token` 的 `sub`、`email` | 只做 macOS；不碰 `~/.gemini/oauth_creds.json`（那是 Gemini CLI 的）。参考 `agy_account/keychain.rs` |
| cursor | 钥匙串 `cursor-access-token` / `cursor-refresh-token`（account `cursor-user`）+ `~/.cursor/cli-config.json` 的 `authInfo` | `authInfo.email`、`authInfo.userId` | 切换时三处一起写：两条钥匙串 + `authInfo`。CC Switch 没做，需要实测 `security` 读写是否弹框 |
| grok | `~/.grok/auth.json` | JWT 的 `email`、`sub` | `grok login` 会整份覆盖，切换就是换回这个文件 |

### B 档（实现前要在装了并登录过的机器上确认）

| 运行时 | 凭据位置 | 身份字段 | 风险 |
|---|---|---|---|
| claude | 钥匙串 `Claude Code-credentials`，没有时回退 `~/.claude/.credentials.json` | 凭据里的 OAuth 账号信息；`~/.claude.json` 的 `userID` 只是哈希，不能当邮箱显示 | `~/.claude/settings.json` 的 `env.ANTHROPIC_*` 会覆盖登录（本机就指向 CC Switch 的本地路由），检测到时只提示「当前由环境变量决定」 |
| gemini | `~/.gemini/oauth_creds.json` + `settings.json` 的 `security.auth.selectedType`；Key 模式在 `~/.gemini/.env` | `oauth_creds.json` 的 `id_token` 邮箱 | 要和 agy 的钥匙串分开 |
| qwen | `~/.qwen/oauth_creds.json` + `settings.json` | `id_token` 或 `resource_url` | 本机未安装登录，格式取自 Hermes 的读取代码 |
| copilot | Copilot CLI 自己的 token（钥匙串或 `~/.copilot/`），另有 `gh` 的 `~/.config/gh/hosts.yml` | GitHub `login` | CC Switch 的 Copilot 账号走路由注入，**不是**改 CLI 登录，不能直接搬；需要实测 Copilot CLI 的存储位置 |

### C 档（「账号」其实是供应商配置）

| 运行时 | 快照的文件 | 显示什么 |
|---|---|---|
| opencode | `~/.config/opencode/opencode.json(c)`、`~/.local/share/opencode/auth.json` | 默认 `model` 的供应商 |
| pi | `~/.pi/agent/auth.json`、`settings.json`、`models.json` | `defaultProvider` |
| openclaw | `~/.openclaw/openclaw.json` | 默认模型的供应商 |
| hermes | `~/.hermes/config.yaml`、`auth.json`、`.env` | 默认供应商 |
| mcode | `~/.minimax/config.yaml` | `defaultModel` |
| deveco | `~/.config/deveco/deveco.jsonc` | 默认供应商 |

C 档切换会覆盖整份配置，**用户在 CLI 里改过的其他设置（MCP、权限等）也会被换回快照时的样子**。所以：

- 只快照和账号有关的文件（`auth.json` 这类）。
- 配置文件不整份收，只收和账号有关的字段（`JsonField`，JSON Pointer 指向如 `opencode.json#/provider`、`settings.json#/defaultProvider`），写回时只改这几个键，MCP、权限等其他设置原样保留。
- 切换前总是先把当前 live 收回库里，所以不需要额外的改动比对。

### D 档（第一期不切换）

| 运行时 | 已知位置 | 原因 |
|---|---|---|
| codebuddy | `~/.codebuddy/`，登录走 `/login` | token 文件未知 |
| codearts | `~/.codeartsdoer/` | 未知 |
| qoder / qoderclicn | `~/.qoder/.auth/`、`~/.qoder-cn/.auth/`（有事务锁文件） | 凭据加密且带事务，备份写回风险高 |
| traecli | `~/.trae/` 下 sqlite | 企业浏览器登录，存在数据库里 |
| kiro | `kiro-cli login` | 未知 |
| reasonix、dim、dsh、zeroclaw、omp、qwenpaw | 各自目录 | 未发现账号文件，或协议里本来就没有登录（zeroclaw 的 ACP `authMethods` 为空） |

D 档显示：从最近一次运行或模型列表的报错判断「未登录」（已有先例：`runtime_models.rs` 里 Cursor 返回空模型时提示 `cursor-agent login`），并提供「在终端登录」按钮。

## 3. 后端设计

新建模块 `src-tauri/src/runtime_accounts/`：

```text
runtime_accounts/
  mod.rs        对外命令用到的服务：status / switch / remove / rename
  registry.rs   每个运行时的凭据描述（下面的 CredentialSpec），D 档不登记
  store.rs      Multara 自己的账号库读写（原子写、0600、进程内锁）
  item.rs       单个凭据项的读、写、比对：文件 / 钥匙串
  identity.rs   从凭据里取身份：解 JWT、读 JSON 字段
  keychain.rs   macOS 经 /usr/bin/security 读写；测试用内存实现
```

### 3.1 凭据描述：用数据而不是每个 CLI 写一套代码

```rust
pub struct CredentialSpec {
    pub runtime: &'static str,
    pub tier: Tier,                     // A / B / C
    pub items: &'static [CredentialItem],
    pub identity: IdentityRule,         // 从哪一项的哪个字段取身份
    pub lock: Option<LockRule>,         // 例如 Kimi 的 proper-lockfile
    pub login_command: &'static str,    // 「在终端登录」时运行的命令
    pub platforms: &'static [Platform], // 钥匙串类只登记 macOS
}

pub enum CredentialItem {
    File { path: HomePath, optional: bool },
    Keychain { service: &'static str, account: &'static str },
}
```

大多数运行时只需要在 `registry.rs` 里加一条描述。只有身份字段特殊的（Kimi 要调 `/me` 取昵称、Codex 要判断 keyring 模式）才写专门的函数。路径从 `cli-catalog.json` 已有的 `home` / `mcpHome` 推不出来，单独登记，不改 catalog 的结构。

### 3.2 账号库

位置：`<app_data>/runtime-accounts/<runtime>.json`，0600，不进导出和同步。

```json
{
  "version": 1,
  "current": "acc_8f2c",
  "accounts": [
    {
      "id": "acc_8f2c",
      "identityKey": "sub:1048...",
      "label": "me@example.com",
      "capturedAt": 1793414661923,
      "items": [
        { "kind": "file", "path": "~/.codex/auth.json", "content": "<base64>" },
        { "kind": "keychain", "service": "gemini", "account": "antigravity", "value": "<原样字符串>" }
      ]
    }
  ]
}
```

- `identityKey` 用稳定 id（`sub`、`userId`）；取不到时用凭据内容的 SHA-256，并在界面上显示为「未命名账号」，允许用户改名。
- 文件内容和钥匙串值**原样保存**，不解析、不改字段，CLI 以后加的字段也能带走（agy 的做法）。
- 不存在的可选文件记成「无」，切换时会删掉 live 里的同名文件（Codex 切到 API Key 模式时就需要）。

是否把账号库放进系统钥匙串而不是文件：第一期和 CC Switch 一样用 0600 文件，Windows/Linux 也能用；如需更严格，后续把 `content` 换成钥匙串里的引用即可，结构不变。

### 3.3 切换流程

```text
switch(runtime, targetId):
  1. 检查：运行时是内置的、平台支持、目标账号存在
  2. 有本运行时的任务正在跑 → 拒绝，提示先停止（避免进程中途读到另一份 token）
  3. 拿锁：Multara 进程内锁 + CLI 自己的锁（如 Kimi）
  4. 读当前 live 凭据 → 取身份
       是已收录账号 → 用 live 内容更新它（拿到 CLI 刷新后的 token）
       不认识       → 自动收录为新账号
  5. 把目标账号的各项写回：文件原子写，钥匙串整条覆盖
  6. 再读一遍 live，身份等于目标 → 成功；不等 → 用第 4 步读到的内容回滚并报错
  7. 更新 current；检测到外部有同名 CLI 进程在跑时，提示「已打开的会话仍用原账号，可能把原账号写回去，请重开」
```

第 4 步是最重要的一步：CLI 会自己刷新 token，Multara 存的旧 refresh token 可能已经失效。每次切换、每次打开账号面板都先把 live 收回来，能让库里的内容尽量是最新的。

### 3.4 命令

在 `commands.rs` 增加，`lib.rs` 注册：

| 命令 | 作用 |
|---|---|
| `runtime_account_status(runtimeId)` | 档位、是否支持切换、当前 live 身份、账号列表、当前是哪一个 |
| `runtime_account_switch(runtimeId, accountId)` | 第 3.3 节流程 |
| `runtime_account_remove(runtimeId, accountId)` | 只删库里的副本，不登出 |
| `runtime_account_rename(runtimeId, accountId, label)` | 改显示名 |

另有 `runtime_account_summaries(runtimeIds)`（运行时列表上的账号区）和 `runtime_account_login(runtimeId)`（返回内嵌终端要跑的 `{ cwd, command }`）。

「添加账号」不在 Multara 里实现 OAuth：`runtime_account_login` 先把当前登录收进库（免得被新登录覆盖），再由前端在内嵌终端里运行登录命令（如 `codex login`、`cursor-agent login`、`grok login`），面板每 3 秒读一次状态（最多 5 分钟），身份变了就刷新。`runtime_account_status` 每次都会把当前登录自动收进库（新号新建、老号更新凭据，内容没变不写盘），不需要手动保存。这样第一期不用处理各家的设备码和回调，以后需要时再按 CC Switch 的 `auth_start_login` / `auth_poll_for_account` 补上浏览器登录。

所有命令都是阻塞 IO（钥匙串、文件），按 `commands.rs` 里 OAuth 的做法放到后台线程，不占主线程。

## 4. 前端设计

- 运行时列表（和卡片）样式不变：已检测到的内置运行时多一个账号图标按钮（提示当前账号），副标题后面带当前账号名，`kind` 不是 `builtin` 的不显示。
- 点图标打开弹窗 `src/views/RuntimeAccountsDialog.vue`，打开时读一次完整状态（含钥匙串）。弹窗里参考 cc-switch 授权中心列出账号，组件 `src/views/RuntimeAccountGroup.vue`。
  - 每个账号一行：显示名 / 邮箱、保存时间、「使用中」或「切换」、改名、删除（使用中的不能删，删了也会被自动收回来）。
  - 默认显示 3 个，「展开更多」每次多显示 3 个，可以连续展开；「收起」回到 3 个。
  - 未登录显示「使用 xxx 登录」，已登录显示「添加账号」，都打开登录终端。D 档、不能切换的只显示原因和登录按钮。
- 登录终端 `src/views/RuntimeLoginTerminal.vue`：和工作台 Cmd+` 终端同一套 xterm 主题和 `terminal_open` 后端，在用户主目录开一个 shell 并输入 `runtime_account_login` 返回的命令。每 3 秒读一次状态（最多 10 分钟），当前登录变成另一个账号就关闭终端、刷新弹窗和列表。
- 列表数据由 `src/views/runtime-account-summaries.ts` 一次性调 `runtime_account_summaries` 批量取，返回和 `runtime_account_status` 同样的结构；「重新检测」后跟着重读。钥匙串和文件混存的 CLI（Claude、Cursor）在列表上只读文件、按显示名认当前账号，不弹钥匙串。
- 类型和调用都放 `src/services/backend.ts`，文案进 5 种语言。

## 5. 风险与处理

| 风险 | 处理 |
|---|---|
| CLI 刷新 token 后，库里的旧 refresh token 失效 | 第 3.3 节第 4 步每次先收回 live；切到失效账号时 CLI 会要求重新登录，面板标「需要重新登录」 |
| 写到一半失败，CLI 登录被弄坏 | 每项都原子写；写完校验身份，不一致就回滚 |
| 钥匙串弹授权框 | 只用 `/usr/bin/security`；Cursor、Claude 的钥匙串条目要真机验证，弹框的就降为「只显示状态」 |
| 和 CLI 同时写同一个文件 | 有锁的（Kimi）拿同一把锁；没有锁的在第 2 步拒绝运行中的任务，并提示退出外部会话 |
| 环境变量覆盖登录（如 `ANTHROPIC_AUTH_TOKEN`、`OPENAI_API_KEY`） | 检测到时在面板顶部提示「当前由环境变量决定，切换账号不会生效」 |
| 账号库泄露 | 0600、只放应用数据目录、不进导出和云同步、日志里不打印凭据内容 |
| C 档覆盖了用户的其他配置 | 只快照账号文件和配置里的账号字段（JSON Pointer），其他键不动 |

## 6. 分期

1. **第一期**：模块骨架、账号库、文件类凭据；codex（文件模式）、grok、kimi；前端面板和运行时标签。
2. **第二期**：macOS 钥匙串；antigravity、cursor；claude、gemini、qwen 实测后接入。
3. **第三期**：C 档的配置快照；copilot 存储位置确认后接入。
4. **以后**：D 档逐个确认凭据位置后在注册表加条目；按需补 Multara 内置的浏览器 / 设备码登录。

## 7. 测试

- `registry.rs` 每条描述一个单测：在临时 HOME 里放假凭据，验证身份解析、收录、切换、回滚。
- 钥匙串用内存实现（同 CC Switch 的 `AgyLoginStore` trait），默认测试不碰真实钥匙串；真机测试单独加 `#[ignore]`。
- 默认测试不调用真实 CLI，也不读用户真实的 `~` 目录：HOME 通过参数传入，不从环境变量取。
- 前端：面板组件测试覆盖 A/C/D 三种状态和「切换失败回滚」的报错展示。
