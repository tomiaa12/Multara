# 收件箱多标签侧栏技术方案

范围：收件箱打开一条会话后，在对话右侧加一条**悬浮图标条**，点开后是同一块侧栏里的四个模块：**更改、文件、浏览器、终端**。一次只显示一个。本文只定交互和复用边界，不改代码。

对照的是 VS Code **Agents 窗口**（`src/vs/sessions`），不是普通编辑器窗口的左栏。编辑器窗口的文件 / Git / 终端仍留在需求工作台。

## 0. 结论

1. 收件箱中间继续是对话。右侧图标条默认收起，点图标才展开对应面板，再点同一图标收起。没选中会话时不显示图标条。
2. 四个模块共用一个面板槽，不并排四列。
3. 更改、文件、终端从工作台抽成公共组件。工作台和收件箱都调用它们，用 props 区分能力。收件箱第一期只用只读树、只读变更和单个终端画面。
4. 终端进程只有一份。会话清单抽到公共 store，两边附着同一个 PTY。收起面板或离开页面只卸画面，不关进程。
5. 浏览器第一期只做壳：图标、空状态、这条会话时间线里的 http(s) URL。不做内嵌浏览器。
6. 任务属性侧栏（`TaskIssueSide`）保留，不收进这四个模块。

## 1. VS Code 是怎么放的

Agents 窗口里，对话是主区域，右侧是 **Session Activity Bar**（`src/vs/sessions/browser/parts/sessionActivityBar.ts`），开关是 `sessions.showSessionActivityBar`。

| 组 | 内容 |
|---|---|
| `1_sidePanel` | 侧栏开关，以及更改、文件、浏览器、Canvas |
| `2_panel` | 终端和底栏开关。终端在底栏，不和上面的侧栏页挤在一起 |
| `3_github` | 当前对话的 Pull Request / Issue |

更改的视图 id 是 `workbench.view.agentSessions.changes`。文件在辅助栏（`sessions.files.explorer`），没有工作区时是空视图。浏览器由 `workbench.action.agentSessions.openBrowser` 打开。

Multara 没有 Canvas，也不做 GitHub 那一组。收件箱没有编辑器主区和底栏，所以四个模块都放进同一块可收起的右侧面板。终端不另做底栏。

## 2. 现在卡在哪

| 能力 | 现状 |
|---|---|
| 收件箱 | 左列表、中对话、任务属性。网格在 `src/styles.css` 的 `.inbox-page`。`.has-task-side` 和 `.has-file-review` 互斥 |
| 文件预览 | `InboxFileReview`。只有非任务的 `ChatPanel`（`review-in-place`）会打开它 |
| 文件树 | 界面写在 `WorkspaceWorkbench.vue`。`explorer/` 是行、拖拽、选择的纯函数。展开目录是组件内存里的 `Set` |
| 更改 | `SourceControlPanel` 已是独立组件，自带多仓库切换。点变更 `emit` 给工作台编辑区的 `GitDiffEditor` / `CommitMultiDiffEditor` |
| 终端 | `TerminalPanel` 画 xterm，卸载时拆画面、不关进程。有哪些终端记在 `WorkspaceWorkbench` 的 `terminalTabs`。`running-terminals` 只跟踪 id、标题、端口和输出镜像 |

## 3. 抽成公共组件

工作台改成这些组件的一个调用方，收件箱是另一个。同一份界面，不在收件箱再写一套 Git、文件树或 PTY。

| 公共组件 | 从哪抽 | 工作台 | 收件箱第一期 |
|---|---|---|---|
| 文件树 | `WorkspaceWorkbench` 里的树，复用 `explorer/` | 保持新建、重命名、拖拽、删除 | `readonly`。单击打开预览 |
| 更改 | 已有 `SourceControlPanel` | 保持全部 Git 操作 | `readonly`，只传入当前一个工作区 |
| 终端会话 | `terminalTabs` 抽到 store，补上 cwd。`running-terminals` 继续做端口和输出镜像 | 创建、拆分、关闭都走这个 store | 只读这份清单，用来附着 |
| 终端画面 | 从 `TerminalPanel` 拆出铺满容器的 xterm 视图。底栏标签、新建、拆分、配置文件留在工作台外壳 | 外壳包着这个视图 | 侧栏只挂视图 |

抽的时候把「收件箱要弱一点」做成 props，工作台现有操作原样留下。

- 文件树：`readonly` 关掉会改工作区的操作。展开状态由调用方按工作区记，收件箱和工作台各用各的 key。
- 更改：`readonly` 关掉暂存、丢弃、提交、拉取、推送、同步、合并、改分支。只传入一个工作区时，不再画组件内部那层仓库切换。列表 / 树状视图的存储 key 由调用方传入，收件箱不写工作台的 `multara.scm.viewMode`。
- 终端：`terminalClose` 只留给用户在工作台里关掉终端。收件箱收起面板、离开收件箱、工作台组件重新挂载，都不关进程。工作台回到同一工作区时接上 store 里还活着的那批，不再塞一个新的 pending 终端。

`GitDiffEditor` / `CommitMultiDiffEditor` 仍是工作台编辑区的标签内容，这一期不抽。收件箱点变更、点文件都打开现有的 `InboxFileReview`。

## 4. 布局

从左到右：

```
列表 | 对话 | 任务属性或文件预览（两格仍互斥） | 工具面板（收起时宽度为 0） | 图标条
```

- 图标条固定窄宽：更改、文件、浏览器、终端。当前打开的那个保持选中。
- 工具面板默认关。打开后可拖宽度，按模块分开记在本地。
- 再点当前图标，或面板上的关闭，收起面板，图标条还在。
- 窄屏沿用 860px 断点。列表现在会改成上方一行，所以图标条不再占 grid 列，面板盖在详情上。浮层避开右下角的 `.chat-fab`（右 25px、底 42px）。任务属性仍是现在的第三行。
- 从对话点文件：预览占原来的预览列，顶掉任务属性，并收起工具面板。关掉预览不自动打开工具面板。
- 从工具面板点文件或变更：预览打开在预览列，工具面板保持当前模块。关掉预览还能看到树或变更列表。

## 5. 四个模块

工作区从会话来。任务写入收件箱时，`InboxItem.projectId` 只是 `session.projectId`（第一个需求）。全部需求在会话的 `projectIds`，`Task` 上没有这个字段。

1. 用会话的 `projectIds`，空则用 `session.projectId`，再空则用条目上的 `projectId`。
2. 取这些需求下的工作区，按 store 里现有顺序。没有工作区时，更改 / 文件 / 终端显示「这条会话没有工作区」。
3. 多个工作区时在面板顶上切换，默认第一个。不在收件箱里添加工作区。当前选的是哪一个只在这条条目选中期间有效，切走就回到下一个条目的默认工作区。

### 更改

挂只读的 `SourceControlPanel`，只喂当前工作区。点一条变更打开 `InboxFileReview`。不是 git 仓库或没有变更时显示空状态。

不做「仅本会话产生的变更」。那需要另一套会话 diff，留到后面。

### 文件

挂抽出来的文件树，`readonly`。单击文件打开 `InboxFileReview`，和 `ChatPanel` 的 `review-file` 共用同一个 `reviewFile`。预览保持现在的保留 / 还原，这一期不改成只读编辑器，也不在收件箱做编辑器标签栏。

### 浏览器

时间线里没有「打开过的网页」列表。`kind === "browser"` 含搜索、抓取、快照，搜索词不是 URL。

从这条会话已加载的时间线里收集工具输入和结果中的 http(s) URL，按出现顺序去重。点一条走已有的 `openExternalUrl`。没有 URL 时说明「对话里还没有网页」。

不做 Tauri webview、标签页、前进后退，也不把页面交给智能体。

### 终端

挂抽出来的终端画面，会话来自公共 store。

- `cwd` 是当前工作区根目录。这个工作区已经有活着的终端时，附着最近的一个，不新建。
- 同一工作区在工作台里可以有多个。收件箱第一期不画多标签，也不做配置文件选择。
- 收起面板和离开收件箱都不杀进程。

## 6. 状态

不进服务端。

| 状态 | 存哪 |
|---|---|
| 打开的模块，或收起 | `localStorage`，全局一份。切条目时保持 |
| 各模块面板宽度 | `localStorage`，按模块分键 |
| 当前工作区 | 只跟当前选中的条目走，切走即丢 |
| 文件树展开 | 公共树组件的调用方状态，按工作区记，和工台分开 |
| 终端、Git、目录 | 公共 store 和现有后端。收件箱不复制进程 |

## 7. 分期

**第一期**

- 抽出文件树、终端会话、终端画面，并给更改面板加上只读。
- 图标条 + 一个可收起面板。
- 更改、文件、终端走上面的公共组件；浏览器是 URL 列表。
- 和任务属性、文件预览的关系按第 4 节。

**不做**

- 收件箱里改 Git、改文件树、多终端标签、配置文件选择。
- 内嵌浏览器，以及只显示「本轮智能体改过的文件」。
- 图标条拖拽排序、自定义模块。
- 把 `GitDiffEditor` / `CommitMultiDiffEditor` 抽进收件箱。

## 8. 主要改动面

| 文件 | 改什么 |
|---|---|
| 新的文件树组件 | 从 `WorkspaceWorkbench.vue` 抽出。工作台改为调用它 |
| `SourceControlPanel.vue` | `readonly`；单个工作区时不画内部仓库切换；视图模式的存储 key 外置 |
| 终端 store + 终端画面 | 会话清单离开 `WorkspaceWorkbench`。`TerminalPanel` 改为底栏外壳，收件箱只挂画面 |
| 新组件，例如 `src/views/inbox/InboxToolRail.vue` | 图标条和四个面板的切换 |
| `src/views/InboxView.vue` | 挂上图标条；接上工作区、预览和面板开关 |
| `src/styles.css` | `.inbox-page` 增加工具列；窄屏改为浮层，避开 `.chat-fab` |

后端第一期不改。Git、列目录、终端都走现有命令。
