# Multara 详细测试用例

> 版本：1.0 · 适用：桌面端（`pnpm tauri:dev` / 已安装包）  
> 范围：功能 / 交互 / 边界 / 回归；专项 Diff 算法见 [`Diff tracking tests.md`](./Diff%20tracking%20tests.md)  
> 前置：本机至少安装并登录 1 个受支持 Agent CLI；真正改文件、跑智能体须在 Tauri 环境，浏览器 `pnpm dev` 仅 mock。

---

## 自动化（真实 Tauri 冒烟）

`pnpm test`（Vitest）只跑纯函数 / mock 单测，**打不到**本机桌面能力。要对测本文用例的真机路径，用已有 WebView bridge：

1. 终端 A：`pnpm tauri:dev`（等窗口起来，Vite `http://localhost:1420`；Windows 上勿写死 `127.0.0.1`）
2. 终端 B：`pnpm test:e2e:smoke`

脚本 [`scripts/e2e-smoke.mjs`](../scripts/e2e-smoke.mjs) 经 `/__e2e/run` 驱动 [`src/e2e/devBridge.ts`](../src/e2e/devBridge.ts)，在 **Tauri WebView** 里点 UI（含真实 IPC）。若只开了 `pnpm dev`，`assertInTauri` 会失败并提示改用 `tauri:dev`。

- 不代启桌面进程；不并进默认 `pnpm test`
- 依赖 Agent CLI / 选目录 / 飞书等条目会 `SKIP`，仍须手工
- 有需求工作区时会测开文件与保存，并还原编辑内容

## 1. 安装与启动

### TC-BOOT-01 · 首次启动种子数据 · P0 · 功能

**前置**：全新安装或清空应用数据目录后的首次启动。  
**步骤**：启动 Multara。  
**预期**：

- 进入 `/projects`（需求页）
- 存在内置智能体 **Miku**（`system_key=miku`）
- 存在对着 Miku 的欢迎会话
- SQLite 落在 `{app_data_dir}/multara.sqlite3`

### TC-BOOT-02 · 冷启动 bootstrap · P0 · 功能

**步骤**：正常启动应用。  
**预期**：侧栏可点；运行时列表已检测；Skills/MCP 已扫描；无白屏、无未捕获错误弹层。

### TC-BOOT-03 · 浏览器预览限制 · P1 · 边界

**步骤**：仅 `pnpm dev` 打开 Web 预览，尝试打开文件 / 发会改盘的消息。  
**预期**：走 mock，不能真实读写本机文件；`/preview` 可用（DEV）；生产构建访问 `/preview` 应重定向到 `/projects`。

### TC-BOOT-04 · Windows 缺 WebView2 · P2 · 兼容

**步骤**：在无 WebView2 环境安装 NSIS 包。  
**预期**：安装流程提示并引导下载 WebView2，安装后可启动。

### TC-BOOT-05 · macOS Gatekeeper · P2 · 兼容

**步骤**：从未公证构建拖入「应用程序」后首次打开。  
**预期**：若提示已损坏，按 README 执行 `xattr -cr` 后可启动。

### TC-NAV-02 · 面包屑 · P1 · 交互

**步骤**：从需求进入工作台；从任务列表进详情；从智能体列表进详情。  
**预期**：面包屑显示上级与当前短名；点击上级可返回。

### TC-NAV-03 · 浮动聊天显示规则 · P0 · 功能

**步骤**：

1. 在非工作台页观察右下角聊天气泡  
2. 进入 `/projects/:id` 工作台  

**预期**：非工作台显示浮动聊天；工作台右侧自带 ChatPanel，不显示浮动窗。

### TC-NAV-04 · 离开工作台未保存确认 · P0 · 交互

### TC-NAV-05 · 同需求内切换不重复确认 · P2 · 边界

**预期**：不因同项目重复弹出未保存对话框（路由守卫逻辑）。

## 3. 运行时

### TC-RT-01 · 重新检测本机 CLI · P0 · 功能

**前置**：PATH 上至少有一个 catalog 内 CLI（如 `claude` / `cursor-agent`）。  
**步骤**：打开运行时 → 重新检测。  
**预期**：已安装项显示**可用**、可执行路径、并发上限；未安装显示未找到。

### TC-RT-02 · 添加自定义运行时 · P1 · 功能

**步骤**：运行时 → 添加运行时 → 填写本机命令与显示名 → 保存 → 重新检测。  
**预期**：自定义项出现在列表；能被智能体绑定（若 online）。

### TC-RT-03 · 离线运行时不可绑定 · P0 · 负向

**步骤**：创建/编辑智能体，选择 `not_found` 的运行时并保存。  
**预期**：保存被拒绝或给出明确错误（runtime 必须 online）。

### TC-RT-04 · 并发上限 · P1 · 功能

**步骤**：将某运行时并发设为 1；同时对该运行时下两个智能体各发一条会长时间运行的消息。  
**预期**：第二条在队列中等待，第一条结束后再跑；UI 有排队/运行态。

### TC-RT-05 · API 地址类运行时配置 · P2 · 功能

**适用**：Claude / Codex / OpenCode / Gemini / Qwen 等支持自定义 API 的运行时。  
**步骤**：在运行时或账号相关表单填写 API 地址后保存，再发起一次短对话。  
**预期**：配置持久化；请求走配置地址（或 CLI 接受参数），失败时错误可读。

### TC-RT-06 · 运行时账号 / 登录终端 · P2 · 功能

**步骤**：打开运行时账号相关入口；对需要登录的 CLI 走登录流程。  
**预期**：登录状态可刷新；未登录时发消息失败提示明确。

## 6. 需求与工作区

### TC-PJ-01 · 新建需求 · P0 · 功能

**步骤**：需求页新建需求（名称等）→ 保存。  
**预期**：列表出现；可进入工作台。

### TC-PJ-02 · 添加 Git 工作区 · direct · P0 · 功能

**步骤**：为需求添加 Git 目录，选择**直接打开**。  
**预期**：`isolationMode=direct`；pill 显示当前分支；副标题含「正在改真实分支」；文件树根为原目录。

### TC-PJ-03 · 添加 Git 工作区 · worktree · P0 · 功能

**步骤**：添加 Git 目录，选择**隔离**（新建或迁出分支）。  
**预期**：`isolationMode=worktree`；pill 为 Worktree；`workPath` 在应用数据 workspaces 下；智能体改动不影响原分支工作区（除共享对象外）。

### TC-PJ-04 · 添加普通文件夹 · copy / direct · P1 · 功能

**步骤**：分别以隔离副本与直接打开添加非 Git 文件夹。  
**预期**：

- copy：`isolationMode=copy`，副标题「隔离副本」  
- direct：原目录，副标题「原目录」

### TC-PJ-05 · 多工作区 · P1 · 功能

**步骤**：同一需求添加 ≥2 个工作区并进入工作台。  
**预期**：左栏每个 workspace 有独立头、展开与刷新；聊天 cwd/允许目录覆盖这些 `work_path`。

### TC-PJ-06 · 删除需求 / 工作区 · P1 · 功能

**步骤**：删除工作区或整条需求（按 UI 确认流）。  
**预期**：确认后数据与本地隔离目录清理符合产品约定；无残留可点的死入口。

### TC-PJ-07 · 需求分类 / 筛选 · P2 · 交互

**步骤**：若需求页有分类或筛选，切换分类。  
**预期**：列表过滤正确；空态有提示。

## 8. 聊天（三入口）

> 入口：① 工作台右侧 ChatPanel ② 浮动聊天气泡 ③ 任务详情活动区。改聊天相关代码后三处都要回归。

### TC-CH-01 · 工作台发送 · P0 · 功能

**步骤**：工作台右侧选智能体 → 输入 → Enter 发送。  
**预期**：用户消息立刻出现；助手流式 timeline；结束后正文落库可刷新对齐。

### TC-CH-02 · 浮动聊天发送 · P0 · 功能

**步骤**：在 `/tasks` 等页打开浮动聊天发送。  
**预期**：与工作台同一套 ChatPanel 行为；无项目会话 cwd 为用户 home，不乱改目录。

### TC-CH-03 · 任务详情聊天 · P0 · 功能

**步骤**：打开任务详情，在活动/聊天区发送。  
**预期**：消息与任务关联；运行态可见；三入口样式与交互一致（compact 差异可接受）。

### TC-CH-04 · 会话目标切换 agent / squad · P0 · 功能

**步骤**：顶部选择器在智能体与小队间切换。
