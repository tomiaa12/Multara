# 智能体编排（Agent Flow）技术方案

> 状态：方案，未实现。工作流仍在开发中。
> 这台电脑上已有的工作流、运行记录和示例可以重置。旧节点类型、端口、模板变量和按端口交接的代码删掉，不留未接线的实现，也不留第二条执行路径。

## 1. 结论

现有工作流是通用节点图：十几种节点、命名端口、模板变量、草稿和已发布版本、总览会话和节点会话。用户要自己设计数据怎么交接。产品要收成智能体编排：智能体负责做事，工作流负责顺序，数据交接由引擎完成。

GPT 方案里这三件事采纳：

1. 智能体和工作流继续分开。工作流只引用已经建好的智能体或小队。
2. 画布上不再让用户配端口和模板变量。一步的结果自动成为下一步的上下文。
3. 多条出线时，由当前步骤在已画好的线里选一条。打回是指回上游的那条线，并限制轮数。

这三件事不采纳，或改成下面的做法：

| 建议 | 处理 |
| --- | --- |
| 另写一套 Agent Flow 引擎 | 运行循环不重写。删掉的是端口交接、模板和多余节点 |
| 删掉脚本、HTTP、Git 等节点 | 类型、执行器、配置、校验和只为它们存在的测试一起删。不留着不接线 |
| 取消端口 | 端口、模板、类型兼容表和按端口提交输出一并删掉。一步的结果就是正文、状态、会话和元数据 |
| 发布和启用合成一个按钮后删掉版本 | 版本快照保留。主按钮改成「发布并应用」，停用仍单独存在 |
| 总览会话改成聊天 | 总览会话可以继续当运行日志写。收件箱和运行页不再把它当成一次对话 |

本体服务的图不适用。那边没有起点，也没有把结果交给下一步去执行。这里仍是一次运行、有顺序、有选路。

## 2. 用户看到的模型

一条工作流是：开始，然后若干智能体或小队，中间可以插入人工审批，最后结束。

| 画布上的块 | 用户要填的 | 引擎里对应 |
| --- | --- | --- |
| 开始 | 这次运行要收集的内容、允许从哪触发 | 入参只出现在开始节点的表单里 |
| 智能体 | 选谁、这一步做什么、多条出线时谁来选、能否创建子任务 | 没有输入输出端口 |
| 人工审批 | 通过、打回、拒绝，以及打回要不要填写说明 | 决定不是端口名 |
| 结束 | 无 | 收的是上一步的结果正文 |

脚本、HTTP、Git、转换、通知、遍历、子流程、条件分支从类型定义、执行器、节点库和校验里删除。

## 3. 数据交接

用户不再声明端口，也不再写 `{{ inputs.question }}`。

每一步结束，引擎保存同一步结果，至少包括：

| 字段 | 来源 |
| --- | --- |
| `content` | 智能体最终正文；人工审批则是决定和备注 |
| `status` | 这一步的节点状态 |
| `sessionId` | 智能体节点的 `wf-node:` 会话；其他步骤为空 |
| `metadata` | 选路原因、循环轮次、审批决定 |

这些字段写在这一步的节点运行上。不再有端口表，也不再有 `text`、`stdout`、`$out` 这类隐式端口。模板变量从编辑器和执行里删除。

下一步的任务说明由引擎拼好，不经过用户模板：

- 开始节点收集到的全部输入
- 紧挨着的上一步的 `content`
- 若是打回：失败原因、修改说明、当前是第几轮
- 这一步自己的任务说明

默认只带上一步。节点上可以改成「带上从开始到现在的每一步正文」，这是可选项，默认关闭。

开始节点的入参仍然要有名字，因为触发时要知道往哪一格填。这个名字只出现在开始节点的表单里，不出现在后面每个智能体上。集成消息仍填进标记为主要的那一项。

所有工作流都按自动交接执行。代码里不再保留按端口名连线的执行路径。

## 4. 选路和打回

只有一条出线时，步骤结束后沿那条线继续，不询问智能体。

有多条出线时，当前步骤必须选出一条，且只能选画布上已有的目标。两种方式：

| 方式 | 行为 |
| --- | --- |
| 自动 | 智能体在结束前提交 `{ "next": "<节点 id>", "reason": "..." }`。`next` 不在允许列表里则这一步失败，不发明新节点 |
| 人工 | 这一步结束后暂停，运行页上列出可选的下一步，等人点 |

人工审批仍是单独一块：通过、打回、拒绝。它不负责在任意节点之间做通用路由。打回就是审批块上连回某个上游智能体的那条线。

回边只能指回祖先，轮数上限为 1 到 20。超过后这条运行失败，或按该线的配置转人工。不新增「回退节点」。

打回时，下一轮任务说明里必须带上：本轮 `content`、审批备注、循环次数。这些来自上一步结果，不要求用户再映射端口。

选中的下一步记在这次节点运行上。条件分支节点和它的端口名删掉。人工审批的通过、打回、拒绝是决定，不是端口。

## 5. 智能体节点配置

新画布里，智能体节点只显示：

| 项 | 说明 |
| --- | --- |
| 智能体或小队 | 引用智能体菜单里已有的对象 |
| 任务说明 | 这一步要做什么 |
| 上下文 | 默认上一步；可改为从开始到现在 |
| 多条出线时谁来选 | 自动或等人选。只有一条出线时此项隐藏 |
| 创建子任务 | 默认关闭 |
| 超时 | 高级项，默认仍是现有的 120 分钟 |

不显示：输入端口、输出端口、模板插入、正文端口、会话 id 端口。

会话、工具调用、Token 仍由这次智能体运行记录。运行详情里可以打开该节点的会话，会话不是一条独立的工作流收件。

## 6. 版本

版本快照不删。正在跑的那一次绑定启动时的定义，这一点保持。

主路径上的文案和按钮：

| 用户操作 | 引擎行为 |
| --- | --- |
| 编辑、自动保存 | 写草稿 |
| 试运行 | 用当前草稿跑，内部仍是 version 0，界面写「试运行」 |
| 发布并应用 | 校验通过后发布下一版，并启用 |
| 之后的正式运行、集成、自动化 | 跑已发布版本 |
| 停用 | 不再接受新的正式运行，不打断已经开始的 |

列表上不再把「未发布」和「未启用」分成两套必须用户理解的手续。有未发布改动时显示「有未发布改动」和「发布并应用」。停用仍是开关，发布之后默认是启用的。

## 7. 一次运行在界面上的形状

一次工作流运行只有一条主记录 `workflow_runs`。

| 记录 | 界面 |
| --- | --- |
| 运行 | 运行记录、收件箱各一条。收件箱点开就是运行页 `WorkflowRunView` |
| 节点运行 | 只在这次运行的画布和时间线里 |
| 智能体会话 `wf-node:` | 只在点开某个智能体节点时出现 |
| 总览会话 `wf-run:` | 可以继续写入「开始运行」「运行成功」这类引擎日志。不作为收件箱正文，也不再为它建任务卡 |

因此：

- `ensure_overview` 不再调用 `attach_existing_session`。总览不建任务卡。这台电脑上已经建出来的任务卡和收件随工作流重置一起清掉。
- `captureInboxNotice` 忽略 `wf-node:` 和 `wf-run:`。收件箱只保留引擎在运行进入终态时写的那一条，标题是「工作流 · 名称」。
- 收件箱列表不展示 `wf-node:`。

运行页保持现在的画布、时间线、节点详情。节点详情是画布右侧的一栏，不是换掉整页。

## 8. 权限

节点上的「创建子任务」是这一次执行的约束，不是写进提示词里的建议。

现有 `cli.rs` 的 `ensure_workflow_node_scope` 已经拦住工作流节点会话里的任务写入、改项目、开别的工作流、恢复会话、发飞书、画布和终端命令。创建任务仅在该节点允许时放行。

本阶段不扩大拦截面。智能体自己的 shell 仍能碰到环境变量里的数据库路径，这不是操作系统沙箱。方案里不把「提示词里写了不要做」当成权限。

节点权限不能放大智能体本身没有的能力。节点只做收紧：全局不允许的，节点打开也仍然不允许。全局允许、节点关闭的，以节点为准。

## 9. 实施顺序

先重置这台电脑上的工作流、运行记录、示例和因此产生的任务卡、收件。然后删掉旧实现，再接上自动交接。中途不留两套执行路径。

1. 删掉端口、模板变量、类型兼容，以及脚本、HTTP、Git、转换、通知、遍历、子流程、条件分支的实现。
2. 一步的结果只保留正文、状态、会话、元数据。下一步任务说明由引擎拼接。选中的下一步记在节点运行上。
3. 画布只提供开始、智能体、人工审批、结束。智能体配置按第 5 节。
4. 多条出线的自动选路和人工暂停。回边使用 1 到 20 的轮数上限。
5. 「发布并应用」同时发布并启用。试运行在界面上不叫 v0。
6. 总览不建任务。收件箱只进运行页。
