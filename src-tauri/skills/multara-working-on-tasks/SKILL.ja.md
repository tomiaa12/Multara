# タスク

タスクは、割り当てと追跡ができる 1 つの作業単位です。担当者・ステータス・結果を残す必要がある場合、または他のエージェントに任せる、複数ラウンドに分ける場合は、タスクとして作成します。

作業台でこの実行がすでにプロジェクトのワークスペースに紐づいていて、ユーザーがコード変更を求めている場合は、そのまま変更します。コードを変更するために先にタスクを作成しないでください。

## 作成

`multara task create --title "…" [--description "…"] [--assignee <agentId>] [--project <id>] [--status todo|backlog] [--parent <taskId>]`

- `--status` のデフォルトは `todo` です。担当者がいれば、すぐに実行が 1 回キューに入ります。
- `--status backlog`：保存のみで、実行しません。
- `--assignee` を省略すると現在のエージェントに割り当てられます。他のエージェントに割り当てるには、そのエージェントの id を渡す必要があります（先に `multara agent list` を実行）。
- `--project` は省略できます。プロジェクトを紐づけると、実行にそのプロジェクトのワークスペースが付きます。
- `--parent`：親タスクの配下に紐づけます。これにより親タスクの詳細の右側にサブタスクが表示され、親の会話に @ による割り当てメッセージが 1 件書き込まれます。現在のタスク id は環境変数 `MULTARA_TASK_ID` にあります。あるタスクの run の中でサブタスクを作成した場合は、`--parent` を渡さなくても現在のタスクに自動で紐づきます。
- 成功すると、stdout にタスクの JSON（`id` を含む）が出力されます。

## 作業の割り振り（サブタスクを含む）

他のエージェントやスクワッドのメンバーに並行して作業してもらいたい場合は、本文に「○○に割り当て済み」と書くだけにせず、サブタスクを作成して割り当てます。

```bash
multara task create --title "…" --description "…" --assignee <agentId> --parent "$MULTARA_TASK_ID" --status todo
```

- 親タスクは `in_progress` のままにします。割り振ること自体は成果の提出にはなりません。
- すべてのサブタスクが完結（backlog/todo/in_progress/blocked のいずれでもなくなる）すると、システムが親タスクの担当者を再び呼び起こして取りまとめさせます。呼び起こされたらサブタスクの結果を確認し、親タスクを `in_review` / `done` にするかどうかを判断します。
- 同じ相手にサブタスクを作成したうえで、同じ会話での自動 fan-out を期待しないでください。ボードのサブタスクとスクワッドチャットでの割り振りは別の経路です。

## 更新

`multara task update TASK_ID --status done --comment "納品メモ"`

変更できるのは `title`、`description`、`status`、`assignee`、`project` です。`--comment` はシステムメッセージとして、そのタスクの会話に書き込まれます。

## ステータス / 割り当て

- `multara task status TASK_ID todo|backlog|in_progress|in_review|done|blocked|cancelled`
- `multara task assign TASK_ID --to AGENT_ID`
- ステータスを `todo` にしても、未着手に戻るだけで、実行は再度キューに入りません。

## 一覧 / 取得 / コメント

- `multara task list [--status todo] [--assignee <id>] [--project <id>]`
- `multara task get TASK_ID`
- `multara task comment TASK_ID --comment "進捗"`
- `multara task runs TASK_ID`

## ステータスを書き込むのは誰か

システムが自動で行う同期は次のものだけです。

1. タスクが `backlog` / `todo` から実際に実行を開始したとき、自動で `in_progress` になる。
2. 実行が成功し、かつそのタスクに他のアクティブな実行がないとき、まだ `in_progress` であれば `in_review` になる。
3. 実行が失敗し、かつそのタスクに他のアクティブな実行がないとき、まだ `in_progress` であれば `todo` に戻る。

**`done` が自動で書き込まれることはありません。** ゴールが本当に達成されたら、明示的に書き込む必要があります。

作業の進み具合に応じて、CLI でステータスを更新します（ターンの途中でいつでも書き込めます。終わるまで待たないでください）。

| 状況 | ステータス |
|------|------|
| このタスク自体の成果の作成を始めた（実装、調査、設計、レビュー――タスクが求めるものであれば何でも） | すぐに `in_progress` |
| このラウンドでタスク自体の成果を提出し、人の確認 / レビュー待ち | `in_review` |
| まだ終わっておらず、作業を続ける（サブタスクが揃っていない場合を含む） | `in_progress` のまま |
| 外部の依存関係や条件で止まっている | `blocked` |
| ゴールが本当に達成された、またはユーザーが完了を確認した | `done` |
| 質問への回答、雑談、他の人の作業への相談だけで、このタスクの成果は進んでいない | **ステータスを変更しない** |

`done` はゴールの達成を意味し、「この run が終わった」という意味ではありません。スクワッドのリーダーへ：メンバーに割り振ることは成果の提出ではありません。親タスクは `in_progress` のままにし、全体のゴールが確認されてから `in_review` / `done` にします。

## ルール

- 作業台がすでにプロジェクトのワークスペースに紐づいているときは、「先にタスクを作成して」と言って、ユーザーが求めたコード変更を妨げないでください。
- 作成によって割り当て、範囲、権限が変わる場合は、実行する前にプレビューを提示します。
- 進捗はタスクの会話に書きます。更新は短く、タスクの識別子と次のアクションを添えてください。
